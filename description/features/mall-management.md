# 积分商城与奖品发放管理

积分商城管理用于查看商品并跟踪用户兑换后的奖品发放工作。奖品配置列表、新增、商品图片、资料及图片局部修改、商品上下架和数据看板的待发放奖品列表均已接入真实接口。

---

## 奖品配置

管理员进入“平台配置”并选择“奖品”后，可以查看按兑换积分从低到高组织的奖品卡片。卡片使用响应式瀑布流排列，并依据奖品图片的原始宽高比呈现不同高度；宽内容区优先展示四列，较窄空间自动减少列数。列宽变化只调整图片显示尺寸，不改变比例或裁切内容。

组件首次进入时调用 `GET /flame/admin/api/product/list` 获取全部商品，不过滤 `status = 0` 的下架商品。列表为空与请求失败分别显示空状态和重试状态；组件由 `KeepAlive` 保存，切换配置项后不会重复请求。

存在图片地址时，前端通过商品图片中转接口取得二进制图片。图片任务按地址去重，每批最多请求 5 张且整批完成后才进入下一批；网络错误或 `5xx` 最多按 `300ms`、`600ms` 指数退避重试 2 次。成功图片从模糊状态渐进清晰，单张失败回退到内置插画。

瀑布流最前方提供“新增奖品”入口。点击后填写奖品名称、描述、兑换积分和必选图片；图片会保持原比例压缩并转换为 WebP。创建按钮使用 3 秒限时二次确认，连续确认后调用真实 multipart 接口。只有服务端返回 `201 Created`，默认上架的新奖品才根据积分加入现有升序列表；`502` 时关闭旧草稿并重拉列表确认可能已经提交的记录。

卡片正面展示：

- 奖品图片。
- 奖品名称与描述。
- 兑换所需积分。
- 当前是否处于隐藏状态。

点击卡片后会原位翻转至背面，管理员可以局部修改奖品名称、描述和兑换积分。首次保存只将按钮原位切换为 3 秒确认态，再次点击才向 `PATCH /product/{product_id}` 提交；超时或确认期间继续编辑都会取消旧确认。请求只包含变化字段，描述清空为 `null`，积分只有变化时才触发配置窗口校验。收到完整响应后更新卡片，积分变更会在翻回正面后平滑移动至新的升序位置。

选择奖品图片后，前端会限制最长边、逐级压缩并转换为保留透明通道的 WebP，目标约 300KB，预览与上传文件都使用处理结果。保存时变化字段作为 `product` JSON 字符串、WebP 文件作为 `image`，共同通过 multipart 请求提交；图片地址由服务端生成。接口若返回 `502`，代表数据库可能已提交但图片替换失败，页面会强制重拉列表确认服务端最终状态。

编辑面打开时会建立资料快照。返回箭头或按 `Esc` 均撤销尚未保存的名称、描述、积分和图片修改；底部只保留“保存修改”，已由上下架接口成功写入的商品状态不会随资料草稿一起回退。

背面同时提供以下管理操作：

- **下架奖品：** 调用真实状态接口将商品 `status` 调整为 `0`，管理端仍保留弱化卡片供后续恢复。
- **上架奖品：** 调用真实状态接口将已下架商品 `status` 恢复为 `1`。

卡片与按钮首先按列表响应中的状态渲染。点击上下架后，按钮进入禁用提交态；只有完整服务端响应通过校验才更新界面，失败时保持原状态且不自动重试。

> [!WARNING]
> 商品可能已经产生历史兑换记录，因此奖品卡片不提供物理删除入口，只通过上下架控制客户端可见性。

## 奖品发放入口

管理员点击“今日待办”中的“待发放奖品”后，“当前赛季”工作区继续翻页并展示待发放列表。点击列表页的返回按钮后，工作区统一回到当前赛季概览。

当前列表展示：

- 用户与兑换商品。
- 用户所属部门；奖品信息在列表中只展示名称。
- 兑换时间。

列表标题已经明确当前内容均为待发放任务，因此条目不重复展示“待发放”状态标签。

### 数据加载流程

1. 请求 `GET /flame/admin/api/product/pending-distributions` 获取待发放流水，并保持后端按兑换时间升序给出的顺序。
2. 按 `user_id` 查询工作台全局用户目录中尚未保存的用户；已由赛季、项目或审核模块取得的资料直接复用。
3. 对 `product_id` 去重后，以最多 5 个并发请求调用 `GET /flame/admin/api/product/info`，补齐包含历史下架商品在内的奖品资料。
4. 将流水、用户和奖品组合为列表模型，并通过现有头像中转链路渐进显示用户头像。

管理员悬浮任一待发放条目时，页面通过跟随鼠标的浮窗展示该奖品名称、说明和图片；浮窗接近视口边缘时会自动切换到指针另一侧。奖品说明不在列表条目重复展示。商品图片只在首次悬浮时通过 `GET /flame/admin/api/image/product` 请求，加载期间显示动画，解码后缓慢消除模糊；移开时取消未完成请求，成功结果在工作台生命周期内复用。

待发放接口返回空数组时显示“当前没有待发放奖品”。接口或数据异常时显示独立失败状态和重试入口，不把错误解释为空任务。

每条记录提供“拒绝”和“发放”按钮。任一操作首次点击进入 3 秒确认态，再次点击才调用 `POST /flame/admin/api/product/distribute` 并显式提交 `rejected` 或 `distributed`；改选动作会取消旧确认。只有后端响应状态与本次决定一致后才移除条目并同步今日待办数量。拒绝后的退款流水与余额更新完全由后端事务处理；失败时保留任务和行内错误，不自动重放写请求。

## 积分与兑换查询

用户事务中的“积分与兑换”复用运动记录智能查询面板，使用 `rewards` 业务域提供真实的自然语言检索、SSE 进度、人工交互、动态表格、历史轨迹和独立 Excel 导出。

兑换模式不展示记录图片，也不提供表格行点击行为。查询结果只读展示，不执行发放状态修改；积分流水、兑换时间、收件信息和发放状态等字段完全以后端 `rewards` 查询域返回的表头为准。

## 当前限制

- 奖品新增、名称、描述、积分、图片和上下架均已写入服务端。
- 服务端商品图片可以真实显示；新增与编辑时选择的新图片都会转换为 WebP 并真实上传。
- 当前可以确认发放或拒绝发放，但不能填写物流信息，也不能在两个终态之间互相改判。
- 确认发放不修改积分；拒绝发放的积分退还由后端处理，前端不修改商品库存或自行计算余额。
- 图片只按悬浮目标加载，不预取后续奖品；快速浏览大量条目时，未完成的上一张图片会被取消。
