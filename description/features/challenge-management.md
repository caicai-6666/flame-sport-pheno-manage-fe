# 挑战配置管理

挑战配置管理用于维护平台统一的挑战等级、运动项目，以及“项目 + 等级”对应的挑战规则。当前阶段已完成**挑战等级与运动项目概览原型**。

---

## 当前页面范围

管理员在平台配置中选择“挑战等级”后，右侧内容区以卡片网格展示全部等级。每张卡片只承载两项核心信息：

- 等级名称。
- 达成该等级挑战后的奖励积分。

当前使用青铜、白银和黄金三条本地原型数据，奖励积分分别为 `100`、`200` 和 `300`。卡片不展示项目规则，因为规则属于“运动项目 + 挑战等级”的组合配置，不是等级自身字段。

点击任一等级卡片后，卡片原位翻转到奖励积分编辑表单。管理员可以输入非负整数并保存，本地卡片会立即展示新积分；点击“返回”或按下 `Esc` 时放弃本次草稿。

等级网格第一位固定展示“新建等级”加号卡片。点击后，新建表单从内容容器底部升起，管理员需要填写唯一的等级名称和非负整数奖励积分。创建成功后，新等级立即加入本地列表，并按奖励积分从低到高排列。

> [!NOTE]
> 当前新增和修改只作用于本地原型数据，尚未发送真实维护请求，刷新页面后会恢复初始等级列表与积分。

### 运动项目

管理员选择“运动项目”后，右侧内容区以卡片展示走路、跑步、羽毛球、篮球、爬山和健身。

点击任一项目时，卡片会从原位置向中央放大并同步翻转。背面按青铜、白银、黄金划分等级区域，每个等级下的规则统一使用以下形式：

```text
每日步数 — 6000 步
达标天数 — 累计 18 天
```

项目规则来自“项目 + 等级”的唯一组合。不同项目可以使用不同数量和类型的指标，详情区域应按 `rule_content` 数组顺序展示，不将指标写死为固定字段。

项目网格第一位提供“新建运动项目”入口。创建表单分为三个步骤：

1. 按 `project` 填写项目名称、说明、图标和状态。
2. 引用平台已有 `project_level`，为每个等级填写 `project_rule` 的副描述、指标、备注和状态。
3. 按 `project_upload_config` 新增一种或多种凭证类型，并填写上传提示、备注示例、排序和状态。

公共指标名称只录入一次，不同等级分别填写要求值。提交时再按等级拆分为各自的 `rule_content`，避免同一项目的等级规则出现指标名称不一致。

项目卡片背面提供以下管理动作：

- **修改指标**：保持指标名称不变，分别修改各挑战等级下的 `rule_content[].value`；空值不能保存。
- **隐藏项目**：将项目调整为停用状态，但继续在管理端以弱化卡片展示，方便管理员恢复显示。
- **恢复显示**：将已隐藏项目重新调整为启用状态。
- **删除项目**：经过卡片内二次确认后，从当前本地原型列表移除。

> [!WARNING]
> 当前删除尚未执行赛季、用户选择、凭证、排行榜和历史数据引用校验。真实业务中，被历史数据引用的项目应优先停用；具体删除资格由后端校验结果决定。

> [!NOTE]
> 当前新增和指标值修改结果只作用于本地原型数据，尚未发送项目、规则或上传配置维护请求。

## 数据口径

等级名称和奖励积分分别对应 `project_level.name` 与 `project_level.reward`。奖励积分用于赛季结束后的统一结算，不在用户上传单条运动凭证时即时发放。

等级状态对应 `project_level.status`，但本轮卡片未要求展示。后续接入真实数据时，是否同时显示停用等级及其弱化方式需要结合接口和产品交互确认。

项目在各等级下的完成条件来自 `project_rule`。前端不得把某一项目的规则误认为等级本身的通用条件。
