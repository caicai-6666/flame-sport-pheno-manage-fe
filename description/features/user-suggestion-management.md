# 用户意见管理

用户意见管理用于集中查看后端判定为可见的用户意见，并允许管理员将每条意见标记为已优化或拒绝。当前数据看板已经接入意见列表与处理接口。

---

## 当前入口

管理员点击“今日待办”中的“新用户意见”后，“当前赛季”工作区继续翻页并展示意见列表。点击列表页的返回按钮后，工作区统一回到当前赛季概览。

当前列表严格展示接口已有信息：

- 提交用户姓名。
- 通过受保护中转加载的用户头像；没有头像或加载失败时使用姓名首字。
- 用户提交的意见正文；默认显示精简预览，鼠标停留或键盘聚焦时以玻璃气泡完整展示。
- 意见创建时间。
- “拒绝”和“已优化”两个处理按钮。

> [!NOTE]
> 列表接口仍没有返回用户 ID 或已读状态，因此页面不把接口结果解释为真正的“新意见”或“待处理意见”。

## 数据与状态

- 工作台初始化时独立请求 `GET /flame/admin/api/suggestion/list`，没有激活赛季时仍可查看意见。
- 今日待办数量等于接口返回的可见意见数量；加载中显示同步状态，失败时显示 `--`。
- 意见列表不重复展示“可见意见”状态胶囊或条目标签，可见口径只用于接口筛选和数量统计。
- 空数组显示“当前没有可见用户意见”，`500` 或响应异常显示独立失败状态和重试入口。
- 接口顺序由后端按 `created_at`、`id` 倒序保证，前端不再次重排。
- 头像最多并发 5 个并对瞬时错误重试 2 次，列表主体不等待全部头像完成才显示。
- 列表数据完成后由模糊和轻微下移状态缓慢浮现，头像解码完成后再渐进清晰。
- 非空 `avatar_url` 使用 `GET /flame/admin/api/image/avator` 获取图片二进制，不让浏览器直接访问客户端存储路径。
- “拒绝”调用 `POST /flame/admin/api/suggestion/process` 并提交 `rejected`，“已优化”提交 `resolved`。
- 两个动作都需要二次确认：首次点击切换为“确认拒绝/确认已优化”，3 秒内再次点击才提交；超时或改选另一动作会恢复。
- 每条意见独立确认和提交；当前条目提交时同时禁用两个按钮，其他意见仍可处理。
- 接口确认成功后才移除当前条目并同步今日待办数量；失败时保留条目并展示具体错误，不自动重放写请求。

## 处理规则

- 后端允许 `pending` 转换为最终结论，并把重复的相同动作按幂等成功处理。
- 意见已有相反最终结论时，前端保留条目并展示 `409` 冲突提示，避免静默覆盖。
- “已优化”的接口阶段为 `resolved`，后端对应持久化阶段为 `optimized`；前端 API 模型保持使用接口值。
- 管理员令牌失效时由统一认证层清理会话并返回登录视图。
- 正文气泡只改变前端展示状态，不触发额外接口，也不改变意见处理阶段；气泡挂载在页面顶层并跟随列表滚动重新定位，避免被卡片裁切。

---

## 后续待确认

- “新意见”的判定口径和已读状态来源；当前接口只提供可见口径。
- 独立意见详情查询接口及详情交互。
- 意见详情、回复和隐藏操作的产品规则。
- 列表筛选、分页及接口错误处理方式。
- 列表是否应只返回 `processing_stage = pending`。当前列表契约仅按 `status = 1` 筛选，且响应不返回处理阶段，因此页面刷新后可能再次看到已经处理但仍可见的意见。

---

## 当前限制

- 当前可查看和处理列表意见，但暂不支持独立详情、回复或修改可见性。
- 页面不维护已读状态；“新意见”的准确口径仍依赖后端后续补充。
