# 赛季管理

赛季管理用于让管理员查看和新建赛季，并在后续阶段维护赛季基础信息。全部赛季概览和新建赛季已接入后端接口，修改和删除仍处于原型阶段。

---

## 当前页面范围

管理员首次切换进入“平台配置”时才挂载该页面，此前不请求赛季列表。页面默认选中“赛季基本信息”，内容区按时间倒序展示赛季卡片，每张卡片包含：

- 赛季名称。
- 开始日期与结束日期。
- 后端返回的“未开始”“进行中”“结算中”或“已结束”赛季状态。

页面不展示参与人数。`GET /season/list` 不返回要求项目数或参赛统计，前端不从数据库文档反推或补造这些字段。

赛季网格第一位固定展示“新建赛季”加号入口，并与实际赛季数量分开统计。点击后，表单从“全部赛季”容器底部升起，背景列表停止交互。

新建表单当前包含：

- 赛季名称。
- 通过“年 / 月 / 日”滚轮选择的开始日期。
- 通过“年 / 月 / 日”滚轮选择的结束日期。
- 通过滚轮选择的要求项目个数，默认值为 `3`。

要求项目个数复用工作台启动时通过 `GET /project/list` 建立的完整项目目录，并从中筛选 `status = 1` 的当前可见项目，不重复发起接口请求。滚轮最大值取可见项目数量与接口上限 `255` 的较小值；若可见项目不足 3 个，默认值收敛为该数量。项目列表尚未成功取得或当前没有可见项目时，新建赛季入口保持禁用，隐藏项目不计入上限。

日期选择以开始日期为前置条件，赛季持续时间不得少于一个自然月。开始日期与结束日期都计入赛季，因此最早结束日按“开始日期顺延一个自然月，再回退一天”计算；月末顺延时先收敛到目标月末。开始日期变化后，结束日期自动切换到这个最早结束日，结束日期的年、月、日滚轮会排除更早选项，并在提交时继续执行兜底校验。

新赛季必须安排在所有已有赛季之后。页面先查找结束日期最晚的已有赛季，以其结束后的第一天作为新赛季开始日期下限，并从年、月、日滚轮中裁掉更早的日期；如果默认的下一个自然月 `1` 日仍早于该下限，则直接使用下限日期。每次新增赛季后都重新计算最晚结束日期，避免后续赛季与刚创建的未来赛季发生时间重叠。

管理员首次点击创建按钮时先执行本地校验，校验通过后按钮进入 3 秒“确认创建”状态；只有在时限内再次点击才调用 `POST /season/create`。确认超时或修改任意字段会自动恢复，避免提交已经变化的内容。请求期间锁定表单，防止重复创建；只有服务端返回 `201 Created` 且响应字段与请求一致、状态为 `0 / 未开始` 时，页面才插入新卡片并关闭表单。新卡片使用服务端生成的 ID、实际写入的要求项目数及状态，不产生本地主键，也不自行推导状态。

> [!IMPORTANT]
> 前端滚轮用于即时减少无效输入，服务端仍会重新校验赛季重叠、完整日历月和创建瞬间的可见项目数量。冲突或校验失败时保留表单并展示安全提示。

卡片使用运动赛事通行证式封面，整张卡片通过干净的双色主题建立信息层级，不保留参与人数底栏。已结束赛季的正面使用灰阶和较低透明度弱化；进行中赛季以更高饱和度、轻微上浮、双层描边、高对比状态胶囊、动态光带和边缘呼吸效果成为列表中的主要视觉焦点。结算中只保留静态暖色提示，避免与进行中状态混淆。

全部已有赛季当前仅作为只读概览卡片展示，不响应点击，也不提供翻面或居中详情层。只有网格首位的“新建赛季”卡片保留点击交互。

---

## 数据口径

页面通过 `GET /season/list` 读取全部赛季。响应顺序为 `start_date DESC, end_date DESC, id DESC`，前端保留该顺序，并校验 `status` 必须为 `0`～`3` 且 `status_name` 对应正确。加载期间显示同步状态，空数组显示“暂无赛季”，请求失败保留错误与重试入口，不转换为虚假空列表。

请求只在“赛季基本信息”组件首次挂载时发起。整个平台配置页和内部配置子页都使用 `KeepAlive`；离开后再次返回复用已取得的列表，不重复请求。

---

## 当前限制

- 赛季列表已使用真实接口数据。
- 新建赛季已使用真实接口，创建请求不自动重试。
- 暂未接入编辑、删除和状态变更。
- 赛季卡片当前不提供详情查看或进一步跳转。
