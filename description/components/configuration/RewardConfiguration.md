# RewardConfiguration

`RewardConfiguration` 是平台配置中的奖品资料管理组件，通过真实商品目录展示商城奖品，并在卡片背面保留资料维护交互。

> [!IMPORTANT]
> 奖品列表、新增、服务端图片、资料与图片局部修改和上下架接口均已接入。

---

## 组件职责

- 首次挂载时请求全部奖品，保留上架与下架商品并严格校验响应结构。
- 按兑换所需积分从低到高组织奖品数据，并使用响应式瀑布流展示小尺寸卡片。
- 通过受保护的商品图片接口按每批最多 5 张加载图片，并对瞬时异常执行指数退避重试。
- 区分列表加载、空数据和失败状态；失败时提供重新加载入口。
- 在瀑布流最前方提供独立的“新增奖品”入口卡片。
- 保留图片原始宽高比，并结合瀑布流实时列宽计算图片区与整张卡片高度，不再把图片映射到预设高度档位。
- 在卡片正面展示奖品图片、名称、描述、兑换积分和隐藏状态。
- 图片铺满整张卡片正面，资料区以紧凑的底部玻璃浮层覆盖在图片上方，不再排列在图片区下方，也不额外增加卡片高度。
- 点击卡片后原位翻转，在背面局部修改名称、描述、积分和图片；处理后的 WebP 与变化字段在同一次 multipart 请求中提交。
- 修改积分并保存后，等待卡片翻回正面，再平滑移动到新的排序位置。
- 在背面按服务端状态提供上架或下架操作，不提供物理删除入口。
- 对名称长度、描述长度、积分范围、图片格式和图片大小进行前端校验。

---

## 使用方式

```vue
<RewardConfiguration />
```

组件当前没有 `props`、事件、插槽或对外暴露方法，由 `PlatformConfigurationPage` 根据左侧导航状态按需挂载，并通过 `KeepAlive` 保留已加载列表。新增奖品由内部的 `RewardCreateSheet` 采集资料并提交给当前组件。

---

## 新增奖品

1. 瀑布流中的新增入口始终作为第一个布局项。
2. 点击入口后，`RewardCreateSheet` 从奖品容器底部升起，原列表暂时进入不可交互状态。
3. 管理员填写名称、描述、兑换积分，并可选择奖品图片。
4. 表单通过校验后，管理员在 3 秒内完成创建按钮二次确认，再通过 multipart 接口上传资料和 WebP 图片。
5. 只有收到 `201 Created` 后，才使用服务端生成的 ID 与图片地址把默认上架的新奖品加入积分升序瀑布流。

创建请求期间表单与关闭入口锁定，写请求不自动重试。若接口返回 `502`，数据库可能已经创建记录，页面会关闭旧草稿、强制重拉奖品列表并展示同步结果，避免重复创建。

## 数据映射

接口模型与 `product` 数据库文档保持一致：

| 页面字段 | 数据字段 | 用途 |
| --- | --- | --- |
| 奖品名称 | `name` | 商城及管理端展示名称 |
| 奖品描述 | `description` | 奖品内容说明，可为空 |
| 兑换积分 | `points_required` | 兑换奖品需要消耗的积分 |
| 奖品图片 | `image_url` | 奖品图片地址，可为空 |
| 展示状态 | `status` | `1` 为上架展示，`0` 为下架隐藏 |

> [!NOTE]
> 服务端没有图片地址或单张图片加载失败时，卡片使用内置线稿插画占位，不会将占位插画写回 `image_url`。

### 列表与图片加载

- 列表使用 `GET /flame/admin/api/product/list`，空数组展示“暂无奖品”。
- `status = 0` 的历史下架商品不会被过滤，而是以弱化卡片和“已下架”标记展示。
- 有图片地址的商品通过 `GET /flame/admin/api/image/product` 获取二进制内容，不直接访问相对路径。
- 相同图片地址会去重；严格按每批最多 5 张请求，整批完成后才加载下一批；网络错误或 `5xx` 最多重试 2 次，等待时间依次为 `300ms`、`600ms`。
- 图片等待期间使用铺满卡面的渐变骨架、低速流光、呼吸光和轻量加载环，避免后续批次出现空白卡片；成功后先解码，再以淡入、消除模糊与轻微缩放组合进入，并使用图片原始宽高比和当前列宽修正瀑布流卡片高度。
- 单张图片失败只回退该卡片的占位插画；列表失败则显示错误与重试入口。

## 瀑布流布局

- 宽内容区优先展示四列，中等宽度依次回落为三列、两列，窄屏使用单列。缩小的是瀑布流列宽和整张卡片，不在卡片内部缩放或裁切图片。
- 奖品按照积分升序依次放入当前高度最短的列，减少普通网格产生的纵向空洞。
- 页面先按“当前列宽 ÷ 图片原始宽高比”计算自然高度；结果不足以容纳完整背面时，将卡片提升到最小完整高度，并通过 `object-fit: cover` 等比例居中放大图片。图片不会拉伸，较高的图片仍使用其自然比例高度。
- 正面资料区作为固定 116px 的底部浮层叠加在图片上，不参与卡片高度计算，也不会改变图片比例。
- 每张卡片翻转前后的宽高严格一致，编辑状态不参与瀑布流重排，也不会推动周围卡片。
- 正面与背面始终共用同一外框高度。对自然高度过小的图片，页面在正面阶段就适度放大其显示容器，因此翻面时无需再次改变尺寸，背面也无需内部滚动即可完整显示。

> [!NOTE]
> 瀑布流中的视觉横向位置由“当前最短列”决定，因此不能将同一水平行理解为严格的积分顺序；数据处理和键盘访问顺序仍保持积分升序。

## 编辑与排序

1. 点击奖品卡片，卡片原位翻转到编辑面。
2. 修改资料后首次点击“保存修改”，按钮原位切换为 3 秒“确认保存”状态；再次点击才提交，超时或继续编辑都会取消旧确认。
3. 页面只提交相对原值发生变化的字段；清空描述时提交 `null`。
4. 表单通过校验并收到完整服务端响应后更新奖品数据，再翻回正面。
5. 如果积分发生变化，卡片根据 `points_required` 重新升序排列；积分相同时按 `id` 保持稳定顺序。

打开编辑面时，组件会保存名称、描述、积分、图片预览和图片比例的初始快照。左上角返回按钮或按下 `Esc` 都会丢弃本次未保存内容并恢复该快照；底部只保留“保存修改”按钮，避免与返回操作重复。已经通过独立上下架接口成功提交的状态不属于资料草稿，不会被返回操作回退。图片读取结果带有编辑会话标识，退出后尚未完成的旧文件读取不能污染后续编辑。

图片选择支持 PNG、JPG 和 WebP，原图最大 5 MB。浏览器会通过 Canvas 限制最长边为 1600px，并逐级调整 WebP 编码质量与尺寸，目标约 300KB；透明 PNG 的 alpha 通道会保留。界面使用处理后的 WebP 预览并保存其真实宽高比，保存时直接通过 `image` multipart 字段上传生成的 `image/webp` 文件，不提交 Data URL 或客户端生成的 `image_url`。

名称、描述、积分和可选图片通过 `PATCH /flame/admin/api/product/{product_id}` 的 `multipart/form-data` 持久化。变化的文字字段序列化到可选 `product`，WebP 文件写入可选 `image`；仅图片更新时不发送空 `product`。保存期间表单与上下架按钮不可重复操作；常规错误保留草稿。接口返回 `502` 时数据库可能已经提交，页面会舍弃旧草稿、强制重拉奖品列表并提示同步结果，避免继续使用旧表单覆盖服务端最终状态。

## 上下架状态

- 列表返回 `status = 1` 时，卡片正常展示，背面提供“下架”按钮。
- 列表返回 `status = 0` 时，卡片以弱化样式和“已下架”标记展示，背面提供“上架”按钮。
- 点击按钮调用 `PATCH /flame/admin/api/product/{product_id}/status`；提交期间禁用按钮并显示进行中状态。
- 只有服务端完整响应通过字段及目标状态校验后才更新卡片；失败时保留原状态并展示安全提示，写请求不自动重试。

> [!WARNING]
> 商品可能已经被历史兑换记录引用，因此当前管理卡片只提供上下架，不提供物理删除操作。

---

## 校验规则

- 名称必填，最多 128 个字符。
- 描述允许为空，最多 255 个字符。
- 兑换积分必须是 `0` 到 `4294967295` 之间的整数。
- 图片只接受 PNG、JPG 或 WebP，且不超过 5 MB。
