# ProofRecordQueryPanel

`ProofRecordQueryPanel` 是用户事务中的智能查询面板。组件通过 `domain` 切换运动记录与积分与兑换视图，共用真实查询会话、SSE 进度、人工交互、任务历史、动态表格和 Excel 导出。

> [!IMPORTANT]
> 查询会话已接入 `/agent/queries` 正式接口：`proof` 模式使用 `sports`，`exchange` 模式使用 `rewards`。查询历史以 `/agent/queries/cached-record-ids` 返回的当前进程有效 ID 为索引，再按会话的 `domain_key` 筛选对应入口，不注入本地种子记录。

---

## 组件职责

- 以带紫橙渐变描边和左侧三枚动态星芒的多行输入容器承载自然语言查询，保留 2000 字上限与 `Shift + Enter` 换行。
- 全站文字使用项目默认字体栈：优先 `Inter`，中文依次回退到 `PingFang SC`、`Microsoft YaHei` 和系统无衬线字体。全局仍提供标题、正文和说明文字的语义字号变量，供新增界面复用。
- 支持回车发送和 `Shift + Enter` 换行。
- 进入页面后输入区直接可用；多层渐变查询按钮作为输入容器右侧的独立控件，不占用文本输入容器内部空间。
- 空闲按钮显示 `Start` 并以蓝紫冷色发起真实检索；当前任务运行、等待确认或等待澄清时显示红色 `Stop`，点击会调用 `DELETE /agent/queries/{query_id}`，服务端确认后再归档为 `cancelled`；取消请求中暂时显示 `Stopping` 并禁止重复提交。
- 按钮基于 Uiverse dexter-st 的多层径向渐变设计适配：多层以不同周期旋转，黑色标签始终保持清晰；按下时按钮下沉、外投影收短、内阴影加深，标签同步下移并在松开后回弹。查询框仍保留按压与彩色流动动画。
- 将头部左侧改为“查询历史”入口，在顶层任务中心只展示已结束任务；容器完成入场后，左侧任务条目按顺序从左侧缓缓滑入，右侧轨迹详情独立淡入，切换条目时不重复播放入场动画。
- 查询历史入口使用纯 CSS 打字机：纸张、滑架和键盘按同一节奏循环，呈现正在整理查询记录的反馈；入口不再加载 Three.js、创建 Canvas 或占用 WebGL 上下文。
- 展示查询中、等待确认、等待澄清、完成、正常放弃、失败、取消和导出失败状态。
- 每次提交通过 `POST /agent/queries` 创建任务，再使用带 Bearer Header 的 `fetch` 流式读取 SSE；完成态轨迹和表格始终按该任务的 `query_id` 分别读取。
- 打开查询历史时读取最多 100 个后端缓存 ID，并以最多 4 路并发补齐任务状态；轨迹和结果在选中记录后按需获取。
- 最新记录始终插入顶部并默认展开，新查询开始时旧记录自动折叠。
- 合并 JSON 列表内所有对象的键，并按首次出现顺序动态生成表头。
- 在完成态结果表格内按任务独立选择可见列，至少保留一列，便于聚焦字段较多的查询结果。
- 用类型标识明确区分“明细记录”与“聚合结果”。
- 运动记录明细可点击查看照片；积分与兑换结果及两类聚合结果仅用于阅读和导出。
- 在固定结果区域内提供横向与纵向滚动，不带动主页面滚动；当前查询结果表格会截断滚轮事件，避免在表格内滚动时外层轨迹同步移动；纵向滚轮与触控板位移按动画帧限幅，避免长轨迹、长表格和长图高速跳跃造成渲染跟不上。
- 允许展开任意一次历史查询，并独立导出该次查询的 `.xlsx` 文件。

组件当前不负责直接读取数据库、拼接 SQL、执行终审、修改运动记录或更新奖品发放状态。

## 业务模式

| `domain` | 业务内容 | 记录图片 | 强调色 |
| --- | --- | --- | --- |
| `proof` | 运动凭证与审核汇总 | 明细行可打开凭证照片 | 绿色 |
| `exchange` | 商品兑换明细与商品汇总 | 不展示图片 | 橙色 |

两个模式在 `UserAffairsPage` 中使用两个独立组件实例，因此当前输入、运行任务和导出状态互相隔离。缓存 ID 接口返回所有业务域的任务，前端读取状态后按 `domain_key` 拆分运动与积分兑换历史。

## 查询结果约定

正式结果由 `GET /agent/queries/{query_id}/result` 返回。组件使用 `headers[].key` 从 `rows` 中读取值，并用 `headers[].label` 生成可见表头；这允许不同问题返回完全不同的字段集合。

适配后的前端结果示例：

```json
{
  "resultType": "records",
  "rows": [
    {
      "用户姓名": "林嘉宁",
      "运动项目": "跑步",
      "审核状态": "待终审",
      "image_url": "https://example.com/proof/0187.png"
    }
  ]
}
```

处理规则：

- `rows` 必须是 JSON 列表，每一项应为普通对象。
- 除隐藏元数据外，对象键直接作为表头。
- 不同记录包含不同键时，表格展示全部键；记录缺少的字段显示为 `—`。
- 对象或数组类型的单元格会序列化为 JSON 文本。
- 布尔值在页面中展示为“是”或“否”，Excel 中保留布尔值类型。
- 圆角审核状态样式只应用于原始字段键严格为 `review_status` 的列；`review_comment`、备注及其他自然语言列即使出现“通过”或“拒绝”等字样，也始终按普通文本展示。
- 运动查询结果只要行中包含有效 `proof_record_id`、`proof_record.id` 或等价的“凭证记录 ID”展示列，即可通过受保护接口打开该记录的凭证照片；表头原始键名可选，前端会按表头名称和行键名双重识别，不依赖智能体是否额外标记 `resultType`。
- `image_url` 是隐藏兼容元数据，不生成表头、不进入 Excel 导出，也不直接作为图片地址使用。
- `exchange` 模式和 `aggregate` 结果不携带 `image_url`。

`result_summary`、`table_description`、相关性说明、问题列表和统计信息由服务端一并校验并返回。页面直接使用受约束的结果摘要，不展示 SQL、模型原始响应、隐藏推理或工具参数。

## 查询交互

初始状态直接展示带紫橙渐变描边的多行文本输入区：左侧三枚星芒会在悬停或聚焦时按顺序弹跳，不再经过小键帽展开阶段，也不渲染空表头。

审核员可以立即输入查询条件，点击右侧 `Start` 按钮或按回车提交查询，`Shift + Enter` 用于换行。按钮直接展示当前动作：空闲为 `Start`，任务运行中为红色 `Stop`；任务运行中点击按钮可立即请求终止。查询轨迹、表格和相关弹层文字默认不可选中，避免拖拽操作时误选；主查询框与澄清输入框保持正常的文本选择和复制能力。

点击 `Start` 或按回车时，查询框会先产生短暂按压反馈，再平滑进入彩色描边流动状态，三枚星芒持续错峰弹跳；空闲工作区的“想查什么？一键掌握”同步淡出。SSE 每到达一个新事件，页面都会从轨迹底部淡入一个节点，并用连续竖线串成执行链。实时链表中只有最后一条且状态仍为 `running` 的节点使用较大的暖色流体几何动画；推进到下一节点时，组件会记录旧节点在滚动内容中的位置，让流体从原位置向下移动，并在行进中纵向伸长、落位后回弹收束，而不是在链表前端突然重建。该动态节点位于 `v-for` 内，因此组件通过函数模板 ref 保存唯一 `HTMLElement`，并在测量与动画前防御检查，不能让局部动效异常中断 SSE 消费。SSE 异常会以“实时连接暂不稳定”节点进入当前链表，不再显示为输入框错误；连接恢复并收到下一条事件后，再追加“实时连接已恢复”节点。连续波动只保留一个等待节点，避免挤满业务轨迹。早先的运行事件与等待、成功、失败等节点均恢复为静态状态圆点，避免多处动画干扰阅读。后端连续返回 `result` 阶段完成与最终 `query_completed`，且两者摘要相同时，页面会合并重复节点，只保留最终“查询完成”；若仍保留“查询结果已完成”阶段节点，则只显示它的标题，不重复展示摘要内容。查询结束后，按钮恢复蓝紫色 `Start` 状态，颜色与阴影渐隐恢复，但终态轨迹不会被清空；完成态的深色结果表格会直接接在最后一个轨迹节点下方，以保留适度横向留白的抽屉形态从底部升起。结果摘要只在最后一个“查询完成”节点展示，当前查询的下载表格按钮紧随该节点右侧，并使用靛色底部叠层；历史结果的列选择与下载按钮才悬浮在表格右上外缘，不额外形成工具栏行。表格仅保留顶部圆角和向上的立体阴影，底沿沉入容器并由容器裁切；表头固定且表体可独立滚动，不会为了造型遮挡最后一条业务数据。只有管理员提交下一次有效查询时，上一轮轨迹与表格才会作为整体淡出并切换到新任务。

收到 `interaction_required` 时，页面从工作区底部升起交互框。`confirmation` 展示后端提供的选项；`clarification` 根据 `allow_free_text` 展示最多 1000 字的自由输入，也可同时展示受控选项。选项与自由输入提交均使用实体控制台按键：浅色、深灰或橙色键帽按操作语义区分，不额外包裹黑色外框；按下时切换为内嵌阴影。回答成功后交互框收起，操作员回答先作为本地节点加入实时轨迹；终态归档时以服务端 `/trace` 轨迹替换，保证审计记录以服务端为准。已取消任务会在归档合并时将唯一的取消终态节点固定到链表末尾；后端因并发写入暂未返回该节点时，页面补入本地终态，避免取消被后续过程节点淹没。

每次提交会先在主页面创建一条当前任务，并逐步追加轨迹。任务进入终态后才归档到查询历史，归档记录包含：

- 本次提示词。
- 检索内容摘要。
- 查询时间。
- 结果行数和列数。
- 按时间追加的智能体查询轨迹。
- 当前任务状态。

任务详情与结果表格是两个独立资源：终态轨迹接口返回 `query_id`、问题、状态和 `entries`；完成态再按该 `query_id` 请求结果数据。页面分别缓存两份数据，并在表格位置展示加载或失败状态，不把结果行塞入轨迹响应。

历史记录按新到旧排列，只允许包含 `completed`、`abandoned`、`failed` 和 `cancelled` 等终态。头部“查询历史”按钮会打开最顶层任务中心，左侧列出归档任务，选中后在右侧以只读方式展示从接收查询到结束的完整轨迹；查询问题标题下不重复展示结果摘要。`completed` 任务在轨迹之后直接展示动态结果表格，并保留图片查看与 Excel 导出；凭证记录 ID 单元格只展示原始值，不额外插入相机图标。其他终态只展示结束原因和轨迹。

任务状态完全由创建响应、SSE 事件和交互响应驱动。SSE 连接意外关闭时，前端先读取会话状态，再使用最后事件序号自动续接；服务端返回 `404` 时按会话失效收口。查询创建阶段点击中止会先记录取消意图，获得 `query_id` 后立即发送真实取消请求，避免后台任务遗留。

查询历史以缓存 ID 接口的倒序结果为准。列表阶段只读取每个 ID 的任务状态和问题摘要，并过滤运行中、等待确认与等待澄清任务；选中记录时才读取 `/trace`。轨迹加载失败可就地重试，缓存 ID 列表整体失败时保留当前页面已有历史并提供重新读取入口。

历史轨迹默认处于摘要态：仅展示前两条与后两条节点的标题，并以“已省略 N 个中间步骤”连接；不显示时间、阶段、消息、选项或回答详情。省略节点中的三点使用 CSS 圆点绘制，避免微型节点因字面宽度溢出。点击摘要节点或“展开完整轨迹”后，中间节点从中心向两侧成对、以较缓的错峰淡入；收起时沿同一节奏淡出，待中间节点基本收束后再显示摘要。轨迹与结果表格属于同一详情内容流，每条轨迹的高度变化会逐帧将表格向下推，并通过右侧详情区域统一滚动查看；每次重新选择历史任务时均回到摘要态。

### 任务状态

| 状态 | 含义 | 是否终态 |
| --- | --- | --- |
| `running` | 后台正在处理 | 否 |
| `waiting_for_confirmation` | 等待确认对齐需求 | 否 |
| `waiting_for_clarification` | 等待补充业务事实 | 否 |
| `completed` | 查询与结果整理完成 | 是 |
| `abandoned` | 用户拒绝继续或智能体基于明确原因正常放弃 | 是 |
| `failed` | 模型、校验、数据库或内部处理失败 | 是 |
| `cancelled` | 用户取消、等待超时或应用关闭 | 是 |

等待澄清时，管理员在主页面提交补充文字；等待确认时选择服务端给出的操作。两者都通过交互回答接口推进工作流。进行中任务通过右侧渐变按钮调用取消接口，服务端确认后转为 `cancelled` 并归档。历史页不提供输入、确认或终止操作，避免已结束任务被再次修改。

## 记录照片查看

点击带有效 `proof_record_id` 的 `records` 结果行，可打开对应的凭证照片。照片查看器会展示用户、项目和运动日期，先显示读取状态，再通过管理端受保护图片接口取得二进制并以 Blob URL 呈现；图片读取完成后以缓慢淡入和轻微上浮进入。长图在查看器内部纵向滚动，不改变主页面位置，并复用查询面板的逐帧限幅，防止高速滚轮导致图片跨越过远。

同时支持：

- 用鼠标点击记录行打开。
- 用 `Enter` 或空格键打开当前聚焦记录。
- 点击遮罩、关闭按钮或按 `Escape` 关闭。
- 照片加载失败时显示独立错误状态。

> [!NOTE]
> `image_url` 仅为结果兼容元数据，不会直接交给浏览器加载。页面从 `headers[].key = proof_record_id` 或 `proof_record.id` 对应的行值获取凭证主键，并调用 `/image/proof_record/{proof_record_id}`；关闭、切换或卸载查看器时释放 Blob URL。

历史页面每次打开都会重新读取后端缓存 ID，因此刷新页面后仍能发现当前进程保留期内的任务。后端服务重启或任务超过 TTL 后，ID 不再由索引接口返回，前端也不会保留陈旧占位。

## Excel 导出

导出工具位于 `src/utils/exportDynamicJsonTable.js`，使用项目已有的 `exceljs` 依赖，并在点击导出后动态加载。

工作簿包含：

- 查询结果标题。
- 本次自然语言查询条件。
- 按 JSON 键顺序生成的动态表头。
- 当前结果中的全部数据行。
- 冻结表头、自动筛选、交替行底色和按内容限制后的列宽。

每条展开记录拥有独立的“下载本次 Excel”按钮。导出函数只接收该历史项的提示词和已按 `query_id` 读取的结果，不读取最新查询的共享状态，因此展开旧记录时不会误导出其他批次。结果尚在读取、读取失败、没有有效结果或其他记录正在生成文件时，按钮不可用。

`image_url` 不进入导出列，避免将凭证存储地址当作普通业务数据泄露到表格。

结果表格右上外缘提供不透明的漏斗字段筛选按钮和清晰的深色“下载表格”实体按钮，不额外占据一行。两者共享深绿实体外层、浅色描边和立体投影；漏斗按钮内部另有与下载按钮右侧图标区一致的深色叠层，保证两者配色和材质统一。下载按钮文案在扣除右侧图标区后的可用宽度内居中，悬停后会由右侧图标扩展覆盖文字，两个按钮按下时都会产生实体位移反馈。字段筛选只影响当前页面展示，不改写归档结果，也不影响 Excel 导出中的完整可导出字段。当前查询表格与历史结果表格的表头和单元格都有最大显示宽度，溢出内容显示省略号；只有内容确实溢出时，悬停才会在鼠标附近显示完整值提示。

## 接口与安全边界

- 所有请求复用 `adminFetch` 注入 Bearer Token，并统一处理认证 `303`。
- SSE 使用 `fetch + ReadableStream`，令牌不进入 URL；断线后使用 `Last-Event-ID` 补发事件。
- 前端校验会话、事件、轨迹、交互与表格的最小结构，拒绝任务标识不匹配、无序轨迹和重复字段。
- 会话只在单进程内存保留，服务重启或超过 TTL 后 `query_id` 失效。
- 历史只覆盖后端当前进程仍在内存保留期内的查询；服务重启或 TTL 到期后无法恢复。
- 大结果的服务端限制和是否改为异步导出仍需后续契约明确。

> [!WARNING]
> 自然语言不能直接作为 SQL 交给数据库执行。后台智能体必须在受控查询工具、字段白名单和管理员权限范围内生成结果，前端也不得使用 `v-html` 渲染返回内容。
