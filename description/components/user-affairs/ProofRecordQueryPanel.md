# ProofRecordQueryPanel

`ProofRecordQueryPanel` 是用户事务中的可配置智能查询原型。组件通过 `domain` 切换运动记录与兑换记录策略，共用查询动画、历史折叠、动态表格和 Excel 导出。

> [!IMPORTANT]
> 当前没有后台智能体的正式接口契约，也没有独立的兑换订单与发放状态数据契约。组件使用本地数据模拟响应，不虚构接口地址或请求方式。

---

## 组件职责

- 以完整长度的立体白色空格键承载自然语言查询输入框。
- 支持回车发送和 `Shift + Enter` 换行。
- 进入页面后输入区直接可用，放大镜按钮只负责执行检索。
- 提交时播放按键下压、彩色背景流动和放大镜扫描动画。
- 展示查询中、空结果、查询结果和导出失败状态。
- 将每次查询保存为由“提示词 + 检索内容摘要”组成的可折叠历史记录。
- 最新记录始终插入顶部并默认展开，新查询开始时旧记录自动折叠。
- 合并 JSON 列表内所有对象的键，并按首次出现顺序动态生成表头。
- 用类型标识明确区分“明细记录”与“聚合结果”。
- 运动记录明细可点击查看照片；兑换记录与两类聚合结果仅用于阅读和导出。
- 在固定结果区域内提供横向与纵向滚动，不带动主页面滚动。
- 允许展开任意一次历史查询，并独立导出该次查询的 `.xlsx` 文件。

组件当前不负责直接读取数据库、拼接 SQL、执行终审、修改运动记录或更新奖品发放状态。

## 业务模式

| `domain` | 业务内容 | 记录图片 | 强调色 |
| --- | --- | --- | --- |
| `proof` | 运动凭证与审核汇总 | 明细行可打开凭证照片 | 绿色 |
| `exchange` | 商品兑换明细与商品汇总 | 不展示图片 | 橙色 |

两个模式在 `UserAffairsPage` 中使用两个独立组件实例，因此查询输入、历史记录和导出状态不会相互污染。

---

## 当前响应约定

两种业务模式都通过结果类型与数据列表共同描述一次查询。`resultType` 只允许以下两个值：

- `records`：当前 `domain` 下的逐条明细。
- `aggregate`：分组、统计或汇总结果。

运动记录结果示例：

```json
{
  "resultType": "records",
  "rows": [
    {
      "用户姓名": "林嘉宁",
      "运动项目": "跑步",
      "审核状态": "待终审",
      "image_url": "https://example.com/proof/0187.png"
    }
  ]
}
```

处理规则：

- `rows` 必须是 JSON 列表，每一项应为普通对象。
- 除隐藏元数据外，对象键直接作为表头。
- 不同记录包含不同键时，表格展示全部键；记录缺少的字段显示为 `—`。
- 对象或数组类型的单元格会序列化为 JSON 文本。
- 布尔值在页面中展示为“是”或“否”，Excel 中保留布尔值类型。
- 仅 `proof` 模式的 `records` 每行应包含 `image_url`，用于打开该记录的凭证照片。
- `image_url` 是隐藏交互元数据，不生成表头，也不进入 Excel 导出。
- `exchange` 模式和 `aggregate` 结果不携带 `image_url`。

> [!NOTE]
> 正式接口可以额外返回查询摘要、分页信息和字段展示元数据，但需要先确定稳定契约。若数据量较大，应由后端智能体分页查询，不能一次返回无限列表。

## 查询交互

初始状态直接展示完整长度的立体白色空格键和文本输入区，不再经过小键帽展开阶段，也不渲染空表头。键帽使用顶部高光、侧边厚度、底部键程和投影形成明显的梯台结构。

审核员可以立即输入查询条件，点击放大镜或按回车提交查询，`Shift + Enter` 用于换行。

点击检索或按回车时，查询框会先产生短暂按压反馈，再平滑进入彩色流动状态；放大镜按钮和首次查询的等待区域同步播放扫描动画。查询结束后颜色与阴影渐隐恢复，避免加载状态突然切换。

每次提交会先在检索记录顶部显示“正在检索”缩略项，并立即折叠已有结果。响应完成后生成一条独立历史记录，记录包含：

- 本次提示词。
- 检索内容摘要。
- 查询时间。
- 结果行数和列数。
- 本次 JSON 行数据与动态列。

历史记录按新到旧排列。最新结果默认展开；管理员展开任意旧记录时，其他记录自动折叠。当前展开项也可以再次点击收起。

原型内置三类响应，用于验证动态列：

| 查询意图 | 返回结构 |
| --- | --- |
| 待终审记录 | 凭证、用户、部门、项目、日期、类型、状态和上传时间 |
| 终审拒绝记录 | 用户、部门、项目、日期、状态和审核意见 |
| 部门审核汇总 | 部门及各审核状态数量 |

前两类返回 `records`，表格行带照片图标和点击态。部门汇总返回 `aggregate`，表格行仅用于阅读，不显示照片入口。

`exchange` 模式内置两类响应：

| 查询意图 | 返回结构 |
| --- | --- |
| 兑换明细 | 流水、用户、部门、商品、消耗积分、时间和发放状态 |
| 按商品汇总 | 商品、兑换次数、积分合计与发放数量 |

> [!WARNING]
> 兑换明细字段仅是本地原型展示结构。其中的流水编号和发放状态尚无数据库文档或后端契约，不应据此实现真实接口。

## 记录照片查看

点击 `records` 结果中的任意记录行，可打开对应的凭证照片。照片查看器会展示用户、项目和运动日期，长图在查看器内部纵向滚动，不改变主页面位置。

同时支持：

- 用鼠标点击记录行打开。
- 用 `Enter` 或空格键打开当前聚焦记录。
- 点击遮罩、关闭按钮或按 `Escape` 关闭。
- 照片加载失败时显示独立错误状态。

> [!NOTE]
> 本地凭证样图已移除，当前原型记录不再挂载图片地址。接入真实接口后，应使用后端受保护的凭证图片接口，并由后端处理访问权限和有效期。

历史记录只在当前页面生命周期内保存，刷新页面后恢复为空状态。正式接入后是否持久化查询历史，需要根据后台智能体接口和管理员审计要求确定。

## Excel 导出

导出工具位于 `src/utils/exportDynamicJsonTable.js`，使用项目已有的 `exceljs` 依赖，并在点击导出后动态加载。

工作簿包含：

- 查询结果标题。
- 本次自然语言查询条件。
- 按 JSON 键顺序生成的动态表头。
- 当前结果中的全部数据行。
- 冻结表头、自动筛选、交替行底色和按内容限制后的列宽。

每条展开记录拥有独立的“下载本次 Excel”按钮。导出函数只接收该历史项保存的提示词和结果快照，不读取最新查询的共享状态，因此展开旧记录时不会误导出其他批次。没有有效结果或其他记录正在生成文件时，按钮不可用。

`image_url` 不进入导出列，避免将凭证存储地址当作普通业务数据泄露到表格。

## Props、事件、插槽与暴露方法

| Prop | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `domain` | `String` | 否 | `proof` | 查询业务域，可选 `proof` 或 `exchange` |

当前未提供事件、插槽或暴露方法。组件内部使用本地数据完成原型闭环，接入接口时再根据服务层职责定义数据入口。

## 主要状态

| 状态 | 用途 |
| --- | --- |
| `queryText` | 审核员当前输入的自然语言条件 |
| `pendingQuery` | 当前正在执行的查询条件 |
| `queryHistory` | 按新到旧保存的查询结果快照列表 |
| `isQuerying` | 智能体正在处理查询 |
| `exportingRecordId` | 当前正在导出的历史记录 ID |
| `queryError` | 空查询等输入错误 |
| `exportErrorRecordId` | 导出失败所归属的历史记录 ID |
| `selectedProofImage` | 当前打开的运动记录照片及摘要 |
| `proofImageFailed` | 当前照片是否加载失败 |

## 接口与安全边界

正式接入后台智能体时至少需要明确：

- 请求参数、返回结构、分页或游标规则。
- 查询结果允许出现的实体与字段范围。
- 当前管理员的数据权限、字段脱敏和审计记录。
- 超时、取消、重试与智能体无法理解问题时的错误格式。
- 导出数量上限，以及大数据量是否改为服务端异步生成。

> [!WARNING]
> 自然语言不能直接作为 SQL 交给数据库执行。后台智能体必须在受控查询工具、字段白名单和管理员权限范围内生成结果，前端也不得使用 `v-html` 渲染返回内容。
